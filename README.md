# compile-excel-server

编译助手（compile-excel）的服务端：负责账号登录、分发编译数据、检索手册。管理员把它装在一台内网服务器上，同事的编译助手连上来登录、同步数据；跳板机上另装一个网关，负责上机跑用例。

| 了解安全设计、参与开发 | [安全设计](docs/security.md)、[开发与发版](docs/development.md) |

## 安装

```bash
curl -fsSL https://raw.githubusercontent.com/qingshanfeihu/compile-excel-server/main/install.sh | bash
```

- 支持 macOS（Apple 芯片和 Intel）与 Linux x86_64，不需要先装 Python。
- 安装脚本会核对安装包的 SHA256，先试运行新版本，再替换旧版本；中途失败不影响已装的版本。
- 程序装在 `~/.local/share/compile-excel-server`，命令是 `ces`。脚本会把 `~/.local/bin` 加进 PATH，按提示重开终端即可。
- 其他平台用源码安装，见 [开发与发版](docs/development.md)。

要装指定版本，在 `bash` 前面加上版本号：

```bash
curl -fsSL https://raw.githubusercontent.com/qingshanfeihu/compile-excel-server/main/install.sh | CES_VERSION=0.2.0 bash
```

## 第一次配置

```bash
ces setup
```

向导只问两件事，其余都用默认值：

1. **数据目录**：账号、编译数据、手册、证书、审计日志都放在这里，默认 `~/ces-data`。
2. **给谁用**：
   - 只在这台电脑上用：适合自己先试一试。
   - 给局域网里的其他电脑用：选“自动生成证书”就行。服务会用自带的 CA 签发证书，用户拿到连接串就能自动核对，不用另外配置证书。

装完会显示连接串，并问你要不要马上建第一个账号。中途按 Ctrl+C 退出，下次运行会从断点继续。

## 建账号，把连接串发给用户

运行 `ces` 进入管理菜单，选“2. 账号 → 新建账号”，对应的命令是 `ces users add 用户名`。

给每个用户发三样东西：

| 内容 | 从哪里拿 |
|---|---|
| 用户名 | 建账号时你填的 |
| 访问码 | 建账号时屏幕上显示（只显示一次，也可以存成文件） |
| 连接串 | 管理菜单首页，或者运行 `ces link` |

连接串长这样：`https://192.168.1.20:8900#ca=3a6b5830…`。`#ca=` 后面是证书指纹，编译助手靠它确认连上的确实是你这台服务器。

## 用户怎么连上来

1. 在编译助手里说：“初始化编译工作区，连接串是 `https://192.168.1.20:8900#ca=…`”。
2. 助手会核对证书，然后给出一个网址和一个设备码。
3. 在浏览器里打开网址，确认设备码和助手显示的一致，填用户名和访问码，点“授权登录”。
4. 回到助手继续。构建号会在登录后自动选好；服务端有多个构建时，助手会请你选一个。

服务端用的是自动生成的证书时，浏览器打开网址会提示“证书不受信任”，因为浏览器不认识服务端自带的 CA。助手已经核对过证书，并会给出服务器证书的指纹：在浏览器的证书详情里核对一致后继续访问即可。不想每次都看到提示，可以按助手给的命令把 CA 证书加入系统信任。

## 日常管理：`ces` 管理菜单

```
════════════════════════════════════════════════════════════
 compile-excel-server 管理菜单                    版本 0.2.0
════════════════════════════════════════════════════════════
 服务      ● 运行中            开机自启    是
 连接串    https://192.168.1.20:8900#ca=3a6b5830…
 证书      https，内置 CA 签发
 编译数据  1 个构建；已发布：BUILD_10_5_0_585 → 3f2a91c07d1e
 账号      12 个（停用 1）     服务客户端  2 个
────────────────────────────────────────────────────────────
   1. 服务管理        启动、停止、重启、看日志、开机自启
   2. 账号            新建、停用、重置访问码、修改权限
   3. 服务客户端      网关、发布器用的密钥
   4. 编译数据        导入、发布、回滚、校验、清理
   5. 手册与旧版工件  知识库手册、旧版工件、构建号、KMS 地址
   6. 连接与证书      连接串、重新签发证书、网关证书
   7. 客户端配置      下发给用户的网关、门户、缺陷系统地址
   8. 审计日志        复核、轮换
   9. 重新配置        重新运行配置向导
  10. 更新            更新到最新版本
  11. 卸载
   0. 退出
```

- 账号、构建、包都按编号选，不用手打名字。
- 会让别人掉线、会删东西的操作，先说明后果，默认选“否”。
- 每一步做完都会显示对应的命令，用熟了可以直接敲命令或写进脚本。全部命令见 [服务端运维](docs/server-admin.md)。
- 想开机自动启动：菜单“1. 服务管理 → 开启开机自启”。Linux 上要管理员权限，运行 `sudo ~/.local/bin/ces service install`（sudo 找不到 `~/.local/bin` 里的命令，所以写全路径）。

## 发布编译数据

用户同步的是某个构建在 `stable` 通道上的那个包。最简单的发布方式：

1. 菜单“4. 编译数据 → 导入目录”：选构建、选数据类别、选目录，导入后进入待发布（`candidate`）。
2. 菜单“4. 编译数据 → 发布到 stable”：用户下次同步就拿到新数据。
3. 发错了：菜单“4. 编译数据 → 回滚 stable 到旧版本”。

从 InfoTest 工作站或已收敛的数据目录批量发布，见 [发布编译数据](docs/publishing.md)。

## 更新与卸载

| 操作 | 命令 |
|---|---|
| 更新到最新版 | `ces update`（数据目录和配置不动，服务会自动重启） |
| 卸载程序，保留数据 | `ces uninstall` |
| 连数据一起删除 | `ces uninstall --purge`（账号、编译数据、审计日志都会删除，无法恢复） |

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 用户初始化时提示“这个地址上的服务不是 compile-excel-server”或 404 | 地址里少了端口（默认 8900）。让用户用 `ces link` 显示的完整连接串 |
| 用户提示证书不受信任 | 用户没用带 `#ca=` 的连接串。把 `ces link` 的输出原样发给他 |
| 用户提示证书里没有这个地址 | 用户用了证书里没写的地址（比如域名或映射出去的 IP）。菜单“6. 连接与证书 → 重新签发服务器证书”，把这个地址加上，再重启服务 |
| 别的电脑连不上 | 运行 `ces status`：连接串是 `127.0.0.1` 说明只监听本机，重新运行 `ces setup` 选第 2 项；否则检查防火墙是否放行了端口 |
| 服务器有多块网卡，连接串里的地址不对 | 运行 `ces link --host <用户能访问到的地址>`（菜单“6. 连接与证书 → 设置连接串里的地址”），证书里没有这个地址时会自动补上，重启服务后生效 |
| 用户忘了访问码 | 菜单“2. 账号 → 重置访问码”，把新访问码发给他 |
| 授权页显示“没有获得的权限” | 用户的账号没有这项权限。需要的话，菜单“2. 账号 → 修改权限” |
| 服务起不来 | `ces log` 看最后 40 行日志 |
