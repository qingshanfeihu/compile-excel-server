# 安全设计

本篇说明账号、令牌、证书和审计是怎么设计的，供评审和排查问题时参考。日常操作见 [服务端运维](server-admin.md)。

## 登录方式

- 用户登录走 OAuth 设备授权流程：编译助手拿到一个网址和设备码，用户在浏览器里打开授权页，填用户名和访问码。对话里、工作区里都不会出现访问码。
- 授权页收哪些字段由登录方式决定。内置的是“管理员发放访问码”（代码里叫 `private-mock`，名字沿用早期的“私有模拟”，实际就是正式的登录方式）：管理员用 `ces users add` 建账号、拿到访问码，交给本人。
- 同一个账号 15 分钟内连续输错 5 次，锁定 15 分钟。只给真实存在的账号计数，随手填的用户名不占内存。
- 企业统一身份以后作为新的登录方式接入（`auth_backends.py` 的 `BACKENDS`），设备授权流程对外不变，客户端不用改。
- 授权页设置了禁止嵌入和内容安全策略，页面上回显的内容全部转义。

## 访问码、密钥与令牌

| 凭据 | 怎么来 | 库里存什么 |
|---|---|---|
| 访问码 | 服务端生成的 144 位随机串 | 加盐 HMAC-SHA256 |
| 服务客户端密钥 | 服务端生成的 256 位随机串 | 加盐 HMAC-SHA256 |
| 访问令牌、刷新令牌 | 服务端生成的随机串 | SHA-256 |

- 访问码和密钥都是高熵随机串，不怕离线穷举，所以用 HMAC 而不是慢哈希，校验是微秒级；校验放在有上限的线程池里，不占事件循环。
- 早期版本写入的 PBKDF2 哈希照样认，下次校验通过时（用户登录、客户端取令牌或核验令牌）自动换成新格式，不需要迁移步骤。
- 访问令牌默认 15 分钟，刷新令牌默认 7 天，刷新令牌每用一次就换新的。已经换掉的刷新令牌被再次出示时，视为泄露，同一族令牌全部撤销。
- `POST /revoke` 撤销自己的令牌。停用账号、重置访问码、修改权限、换客户端密钥都会让相关令牌失效。

## 权限

客户端申请的权限与账号拥有的权限取交集后签发。令牌能用的权限，始终是签发时的权限与账号**当前**权限的交集：

- 在授权页批准之后、兑换令牌之前，账号被停用、删除或重置了访问码，兑换一律拒绝；权限被收回的只签发剩下的。
- 刷新令牌同样按账号当前的权限续签，一项都不剩就拒绝。

| 权限 | 授权页上的说明 | 默认给用户 |
|---|---|---|
| `artifacts:read` | 下载旧版工件 | 是 |
| `docs:query` | 检索手册 | 是 |
| `bundles:read` | 下载编译数据 | 是 |
| `config:read` | 读取组织配置（网关、门户等地址） | 是 |
| `jumphost:run` | 在跳板机上租床、跑用例 | 是 |
| `jumphost:admin` | 初始化设备（管理员权限） | 否 |
| `bundles:publish` | 发布编译数据（发布器用） | 否，给发布客户端 |
| `introspect` | 核验登录令牌（网关用） | 否，给网关客户端 |

网关用自己的客户端密钥调用 `POST /v1/introspect`（HTTP Basic 认证），确认用户的令牌是否有效、有哪些权限。核验结果最多缓存 30 秒（且不超过令牌本身的有效期），令牌在服务端撤销后，最迟 30 秒网关就会拒绝它。

## 下发给客户端的配置

`/v1/config/client` 只下发非机密的地址。键名像凭据的、地址里带账号口令的一律拒收。个人门户账号不保存（客户端扫码登录）。

## 未登录就能访问的接口

这些接口都有上限，超了回 413 或 429：

| 限制 | 上限 |
|---|---|
| 表单请求体 | 8 KiB |
| `POST /v1/bundles` 清单 | 16 MiB |
| 单个上传文件 | `CES_MAX_BLOB_BYTES`（默认 2 GiB）；声明的长度超限直接拒，不声明的边读边数 |
| 待处理的设备码 | 全局 1000 个，同一来源地址 `CES_MAX_PENDING_FLOWS_PER_IP` 个（默认 20） |

- `/healthz` 只回 `{"ok": true, "service": "compile-excel-server"}`，构建号、登录方式、KMS 地址都不在这里透出（登录后看工件清单 `/v1/artifacts/manifest`；本机 `ces status` 也能看到）。
- `/ca.pem` 只回内置 CA 的证书，私钥不出数据目录。

## 证书与连接串

- 服务监听非本机地址时必须用 https，除非显式确认是可信实验网（`--insecure-lan`）。客户端对非本机地址默认也拒绝明文，要在工作区显式开启。
- 内置 CA 的信任模型和 SSH 首次连接时核对主机指纹一样：指纹由管理员通过别的渠道（连接串）交给用户，客户端先不校验证书下载 `/ca.pem`，算出指纹与连接串比对，对上了才信任它。下载途中被调包，指纹对不上，客户端拒绝并且不保存任何东西。
- 客户端每次使用前都会按配置里记的指纹重新核对工作区里的 `ca.pem`；同一个地址换了 CA，视同换了服务端，旧令牌一并丢弃。
- 客户端只信任“系统证书库 + 这一份 CA”，不会因为连接串放宽对其他站点的校验。下载的 CA 必须恰好是一张证书、严格按 base64 解码，信任库里只装解出来的这一张；拼接多张证书的回应会被拒绝。
- 浏览器不认识内置 CA，授权页会出现证书警告。编译助手已经核对过证书链，会给出服务器证书的 SHA-256 指纹，用户在浏览器的证书详情里核对一致再继续，冒充者的证书指纹对不上。
- 网关的证书由同一个 CA 签发，网关连服务端时也用这份 CA（`[server] ca_file`）。
- 服务器证书两年有效，用 ECDSA P-256 签名；CA 十年有效、只能签发一层证书。CA 私钥丢失或泄露时，删掉 `<数据目录>/tls/` 重新运行 `ces setup`，再把新的连接串发给所有用户。

## 审计日志

- 服务端和网关的审计日志都是哈希链：每行带着上一行的 SHA-256，改动或删除中间任何一行都会断链。服务端另用实例密钥（部署时生成）签名每一行。
- 审计日志里不记任何令牌、访问码或密钥。
- 轮换与复核见 [服务端运维](server-admin.md#审计日志)。

## 安装包

- 每个版本的发布页附带 `SHA256SUMS`，安装脚本下载后自动核对；手动下载时可以用 `sha256sum -c SHA256SUMS` 核对。
- 安装脚本拒绝包含绝对路径或 `..` 的安装包，并且先试运行新版本，再替换旧版本。

## 仓库里不放内部资产

- 本仓库只放平台代码、打包脚本和用合成数据写的测试，不放真实工件、手册或凭据。
- 真实工件（晋升模板、框架子集、命令树 XML）、知识库手册、构建元数据都在部署侧的数据目录里；审计签名密钥和证书私钥在部署时生成。
- `tests/test_e2e.py::test_no_internal_assets_in_repo` 是防泄漏检查：仓库里一旦出现内部资产的指纹（真实模板、契约的哈希、内部构建名），测试就失败。
